# 项目审查与修复记录

审查基线为主仓库 `108267c` 及工作区中的 Telnet 实现。virt 旧镜像通过串口登录、`uname` 和三轮双核冒烟测试。下表按可能造成的影响记录问题，验收以对应代码重新构建后的结果为准。

| 优先级 | 问题及影响 | 验收条件 |
| --- | --- | --- |
| 高 | ext4 两个独立打开的句柄缓存各自的 EOF。先后追加 `AAA` 和 `BBB`，实测仅留下 `BBB`。 | 两次写成功后读回 `AAABBB`，第二次追加偏移为 3。 |
| 高 | ext4 流式测试在开发磁盘上删除同名文件并覆盖测试数据。 | 默认运行和指定已有磁盘时均只修改临时盘，源盘校验和相同。 |
| 高 | spawnd 在单一分发线程中等待前台任务退出；子任务请求 exec 或 spawn 时会互等。 | 前台任务能调用 exec 和嵌套 spawn；等待期间仍可处理其他客户端请求。 |
| 高 | 所有子进程共享同一 spawnd 入口，exec 和 kill 只检查数字 handle。 | 子任务可以替换自身，父任务可管理自己的子任务，其他任务请求被拒绝。 |
| 高 | authd 读取持久凭据失败后启用内置 root。 | 持久模式下凭据缺失、不可读或无有效条目时拒绝登录；开发凭据仅在显式无盘配置下启用。 |
| 高 | i.MX6UL 启动项缺少 authd 模块和指向认证服务的 capability。 | 从现有源码构建板级镜像，串口登录成功。 |
| 中 | Telnet 桥回显密码，且正常断线与接收超时都返回零长度，连接和子 Shell 无法回收。 | 密码输入不出现在服务端回显中；空闲连接可继续使用，断开后端口和子任务均可回收。 |
| 中 | SMP 冒烟脚本在零轮测试时返回成功。 | 零轮和非法轮数返回参数错误；正常轮数仍由真实测试结果决定退出码。 |
| 中 | Telnet 测试在累计缓冲区中查找系统名称，启动横幅可能满足 uname 断言。 | 登录后只接受本次命令产生的完整输出，缺少命令输出时报告失败。 |

## 修复与验证结果

以上九项均已在工作区修复。验证使用重新构建的 ARM 用户态和 QEMU 镜像。

| 范围 | 修改与实测结果 |
| --- | --- |
| ext4 数据一致性 | 在追加、读取和截断时刷新句柄所见的文件长度。宿主回归覆盖两个独立句柄追加后读回 `AAABBB`，以及一个句柄截断后另一个读到新 EOF。 |
| ext4 测试用盘 | 流式测试默认创建临时磁盘，传入已有镜像时先复制再测试。两种方式均通过 6 MiB 逐字节复制、截断和读回验证，指定的源镜像测试前后 SHA-256 一致。 |
| 进程等待与权限 | spawnd 保存等待者的回复能力，子任务退出时再回复，分发线程可以继续处理请求。每个子任务使用独立服务入口。前台自替换成功启动目标程序，前台嵌套启动测试成功运行 46 个子任务并返回 Shell。Telnet 会话中等待非子任务得到拒绝，正常断线时服务可以终止自己的子 Shell。跨任务 kill 和 exec 的拒绝分支经过源码核对。 |
| 持久认证 | 凭据缺失或格式无效的临时盘均拒绝登录，已初始化的临时盘和现有开发盘的新副本均可登录。新建 virt 开发盘时写入初始凭据，初始化失败时不发布残缺镜像。无盘开发认证需要板级配置显式启用。 |
| i.MX6UL 启动 | 补齐 authd 模块和服务能力，并修正干净构建中发现的 ARM 运行库汇编源、ext4 并行构建依赖。使用现有内核，从临时构建目录重新编译启动项所需用户态组件并打包。仓库默认启动脚本也已在 QEMU 中验证串口登录和 `uname`。 |
| Telnet 会话与断言 | 由 Shell 负责密码掩码，netd 分别返回接收超时和对端关闭。回归只在本次命令的输出中匹配结果。实际 TCP 会话通过密码掩码、登录、`uname`、外部命令 `ifconfig`、正常断线及服务退出检查。 |
| SMP 冒烟 | `-n 0` 和 `-n abc` 均以参数错误码 2 退出。重建测试镜像后，双核 QEMU 连续三轮通过，分别耗时 10、9、10 秒。 |

## 后续三项修复

| 问题 | 原因与修复 | 验证 |
| --- | --- | --- |
| 开发盘空闲块与 inode 计数偏差 | lwext4 在内存中更新超级块计数，原先到卸载时才写回。virt 的 ext4 服务持续挂载，退出 QEMU 时，位图已经写入，汇总计数仍可能是旧值。服务现在在应答创建、写入、截断和删除等请求前刷新缓存，成功写入位图后再保存变化的计数，并保留挂载状态。 | 修复前超级块多记 1 个空闲块和 2 个空闲 inode。先离线修复副本，再确认主超级块以外的所有字节与原盘相同，最后替换开发盘。`e2fsck -fn` 五阶段通过。QEMU 完成 6 MiB 逐字节复制和截断后直接停止，流式测试同时检查文件内容和盘上计数。 |
| 递归删除目录时误报 inode 校验和错误 | 删除逻辑先修改目录 inode 的链接数和删除时间，分段截断再按 inode 号取引用，此时缓存里的校验和仍是旧值。现在截断前用现有引用更新校验和，并将缓冲区标记为待写。 | 旧版本能复现 inode 12 告警。新版本在 4 KiB 索引目录、1 KiB 非索引目录以及 4 KiB 带日志文件系统上分别创建并删除 32 个文件，均无校验和告警，离线检查通过。 |
| Telnet 断线时出现无效 Pager 告警 | 原来由 telnetd 强制销毁仍在读控制台的 Shell。现在 TCP 断开后，虚拟控制台唤醒读者并返回挂断错误，Shell 的输入线程通知父进程退出，telnetd 等待 Shell 回收后再退出。 | 在双核 QEMU 连续运行 5 轮，每轮先验证远程命令并断线，再重用同一端口登录并在密码提示处断线。10 个会话的 Shell 和 telnetd 均返回 0，串口未出现该 Pager 告警。回归脚本现在将此告警判为失败。 |

修复前的开发盘保存在 `build/virt_disk.img.before-fsck-20261119`。本机 e2fsck 1.45.5 在只读模式下报告计数错误后仍可能返回 0，因此流式测试也会检查诊断文本。

开发盘副本的回归还复现了一个启动时序问题。authd 首次打开磁盘凭据时，VFS 接口探测返回 ENOPROTOOPT（errno 92）。修复后，同一次启动的首次登录触发重新打开，成功读取凭据并登录；使用无效凭据文件的对照测试仍拒绝登录。

本轮三项修复的运行验证覆盖宿主 lwext4 和双核 QEMU virt。实体硬件尚未验证。

### virt 开发镜像的构建耗时

在 Xeon W-2265、Arm GNU 12.3、12 个并行任务下，使用默认 `native-shell` 入口按下列顺序测量墙钟时间。源码与工具链已就绪，冷构建使用新的空输出目录，后续步骤复用该目录。结果为本机一次实测，可在同一台机器上用作回归基线。

| 操作 | 耗时 | 验证结果 |
| --- | ---: | --- |
| 从空目录构建并打包 | 143.49 秒 | 生成内核、用户态和可启动 ELF |
| 随即再运行一次相同构建 | 16.13 秒 | 编译和链接均为零，仍检查依赖并生成启动镜像 |
| `--pkg klog --compile-only` | 9.60 秒 | 检查已有单包和依赖，跳过镜像打包 |
| 更新私有构建目录内 `libklog.a` 的时间戳，再执行 `--pkg klog` | 13.14 秒 | LVGL 等使用方重新链接，发布镜像与构建镜像一致 |

单独修改 klog 源码的实验也验证了新内容进入 LVGL ELF。冷构建后的首次空跑此前触发了 97 次链接，根因是依赖扫描重写了内容相同的 pkg-config 别名。回归现在会检查空跑日志中的编译和链接动作。

顶层入口支持 `make -j12 BOARD=virt O=build all`。比较耗时时应固定板型、入口、工具链、并行数和输出目录的初始状态。Linux Kbuild 同样支持用 `O=` 指定输出目录。[Linux Kbuild 文档](https://docs.kernel.org/kbuild/kbuild.html#kbuild-output)
